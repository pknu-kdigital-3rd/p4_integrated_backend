# 4. 시스템 요구사항 명세서

## 문서 기준

다음 문장은 현재 구현을 검증 가능한 형식으로 재구성한 것이다. `FR`은 기능 요구사항, `QR`은 품질·운영 요구사항이다. 배포 구성에 의존하는 항목의 검증은 구성된 환경에서만 가능하다. 원본 이해관계자 서명이나 성능 목표치를 새로 만들어 넣지 않는다.

## 인터페이스·데이터 기준

- Node 공개 API의 기본 경로는 `/api/v1`이다. 성공 응답의 일반 형태는 `{ "data": ... }`, 오류 응답은 `{ "error": { "code": ..., "message": ... } }`이다. 내부·Python·Go API에는 다른 응답 형태가 있으므로 [컴포넌트 명세](07_subsystems_components.md)를 따른다.
- DB의 `BigInt` 식별자는 JSON에서 문자열로 직렬화된다. 좌표는 GeoJSON에서 `[경도, 위도]`, 라우팅 서비스의 기존 `/api/route` 경로 배열에서는 `[위도, 경도]` 형식이므로 인터페이스별로 구별한다.
- `vehicle_source`는 `CUSTOM`, `BIMS`, `VIRTUAL`을 구분하고, 위치 `telemetry_source`는 BIMS·단말 출처를 구분한다. 가상 차량에는 실제 GPS 출처를 부여하지 않는다.
- 정량적인 FPS·지연·동시 접속·가용성 목표는 승인된 수치가 없어 본 명세에서 미정이다. GPU·네트워크·저장소를 포함한 실제 환경의 부하 시험 결과가 있어야 수치 기준을 정할 수 있다.
